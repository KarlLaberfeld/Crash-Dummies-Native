# Complete instruction text after later title pages

October 21, 2026: all 48 additional full/skip original/native comparisons match,
zero differences. Sixteen cases cover direct Start after pages 1..4 in both
retained histories. Thirty-two more follow actual one/two-player selection on
those pages. Each parent has separate full-text/prompt/fresh-Start and
held-Start/skip controls. These retain Air/easy choices from the accepted
first-page A ancestry; other choices and subsequent turns are separate scopes.

The compared extent includes the complete incoming fade, typed text or its
actual skipped suffix, prompt where applicable, outgoing fade and audio stop.
Totals: 74,144 boundaries, 33,632 displays, 67,264 vectors, 7,712 access polls,
3,248 glyph stores, 70,576 other stores, 294,912 map bytes, 147,456 picture tile
bytes and 201,792 voice rows. Counts overlap their preceding instruction and
menu histories; they are not complete-game counts.

The native incoming-fade/text guards now accept their explicit completed-
carousel origin while retaining first-page absolute checks and all campaign,
geometry, input, audio and storage guards. Fresh Start and held Start execute
existing semantic owners. Original observations never schedule native work.
The source child retains the exact parent instruction file hash, page, actual
player count, complete controls and unchanged observed/unobserved fingerprints.
Origin labels cannot be mixed or silently reduced to first-page selection.
All complete native ancestor CSVs remain byte-identical, and new accesses,
rasters, maps, picture storage and active voice states are compared independently.
Parked voice flags remain distinct from logical playback; the stopped driver's
unused payload and PCM are not qualified by these comparisons.

Use `tools/air_title_text_controls.py ROM --capture INSTRUCTION_CONTROL --out
TEXT_CONTROLS` to prepare both append-only controls. Then use
`tools/selected_text_reference.py capture ROM --capture TEXT_CONTROL
--accepted-control INSTRUCTION_CONTROL --parent-out INSTRUCTION_REFERENCE
--out TEXT_REFERENCE`. The native complete-chain replay uses
`--title-cycle-action-page N --title-cycle-text-exit` for direct Start or
`--title-cycle-players-text-exit` for actual selection. Data stems remain
`.fifth.later.title-*` and `.fifth.later.selected.title-*`, respectively.

`compare-later-batch` extends the relevant accepted instruction manifest with
`selected_base`, `text_control`, `selected_text_out` and the new `native_base`.
The exact previously-qualified instruction records remain the parents; every
new complete native prefix and source attachment is checked again. The public
comparator can also independently requalify the entire parent graph.
Local prefix checkpoints only accelerate uninstrumented reference controls;
source observation still replays the canonical complete history, without any
clock allowance or original-state injection into native execution.

Validation: all 48 cases, 1,863 Python tests and the affected optimized native
owners pass. The full native Windows regression also passes; it proves native
campaign playability, not original parity of the unmeasured campaigns. See
[player/Start scope](LATER_TITLE_PLAYERS.md). The broader [matrix](ORIGINAL_COMPARISON_SCOPE.md)
remains in progress: initial terminal gameplay, two-player turn changes,
other stunts/difficulties/outcomes, further menu/password use, changed scores,
frames/PCM and production scheduling remain open. Original data stay local;
this is not final-release acceptance.
