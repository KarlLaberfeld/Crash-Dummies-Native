# Later-title-page decision comparisons

October 21, 2026: all 24 cases match, zero differences. The matrix is four
later pages, three decisions and two retained histories, using the accepted
first-page A parent. Totals: 231,034 boundaries, 28,838 display/music services,
91,194 vectors, 124,712 raster boundaries, 156,306 polls, 322,230 stores,
245,760 map bytes and 173,028 voice rows. These totals include overlapping
preceding page histories. Each child preserves 374 / 378 complete native
ancestor files plus 9/27/45/63 preceding carousel CSVs for target pages 1/2/3/4.
The optimized diagnostic, 1,795 Python tests and CLI rejection of invalid target
pages pass. All four complete automatic native carousels remain byte-identical
(455 / 459 files per history), independently of these early-stop cases.
Production sources are unchanged; no final-release or automation change.

This scope continues the accepted first-page A action through automatic title
pages, then exercises Start, Select or the Up/Down/Left/Right password sequence
on a selected later page (1..4). Each case ends at the actual outgoing decision:
Start at 0269, Select at 2749, or password entry at 2b4f. The subsequent screen
transition is a separate comparison; these endpoints do not qualify it.

The controls append only fixed button events and host-frame waits. Delay uses
the original 480/960 page durations and the independently qualified 81-display
later-page composition. The observer still requires the intended actual page,
all preceding page/idle groups and the correct branch. A label or elapsed wait
cannot substitute for reaching that state. Two independent unobserved prefix/
full runs and the complete observed hash must agree with the accepted original
ROM/backend/setup. Native replay consumes only decoded assets and raw buttons.

Every completed group before the targeted decision must equal the corresponding
group in an independently accepted complete automatic carousel. All nine native
CSV files for each such group remain byte-identical; the complete earlier native
ancestor files are also checked for every child. The automatic carousel and
shared first-page ancestors are qualified once per batch, while every child
retains its own source and storage/timing comparison. A modified score table
would require a different accepted parent; initial records are the present scope.

Start/Select require a fresh exact edge, the unchanged page index and the correct
retained timer without a final decrement. Password entry requires the complete
four-edge sequence, intermediate selector stores, final selector reset and the
actual outgoing route. No title-page advance store is allowed on those branches.
All display/music work, voices, raster stores, access polls and maps are still
compared. Native timing comes from the existing semantic page/menu owners.

Prepare with `tools/title_cycle_reference.py prepare ROM --action
start|select|unlock --page 1..4 --capture FIRST_ACTION --out CONTROL`, then use
its normal `capture` command with the accepted first-action parent. A comparison
manifest adds `accepted_cycle_base`, `accepted_cycle_control` and
`accepted_cycle_out` to the ordinary carousel arguments. Native replay uses
`--title-cycle-action-page 1..4`, which bounds observation but does not select
which action the native menu reads from the input stream. Wrong/missing routes
or target pages reject. The default complete automatic/A-B carousel is unchanged.

Original recordings, map/voice snapshots, ROM/assets and reference binaries
remain local. These comparisons do not establish Windows scheduler timing,
modified high scores, subsequent Start/player/password transitions, rendered
transition frames, PCM or final release acceptance. See the
[comparison matrix](ORIGINAL_COMPARISON_SCOPE.md) and [acceptance](ACCEPTANCE.md).
