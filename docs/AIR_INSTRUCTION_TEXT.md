# Timed instruction text through 032b

The native diagnostic continues from the map transition through the complete
following Air/Ski instruction. Nonzero glyphs wait five counter services; zero
glyphs do not wait. Each row scroll has five stores (1, 2, 3, 1, 1) separated
by two waits. Native names and Ski quota glyphs come from local UI data. Their
semantic word returns, fresh Start skipping and ordinary glyph writes own their
identified source operations. No cartridge instructions, recorded durations,
vectors or readiness results run in the native process.

The instruction retains selector five for both callbacks and keeps the result
countdown unchanged. Native audio and held/fresh input continue on every display.
The LCD writer owns each readiness poll and intended glyph destination.
Termination clears text speed, anchor and skip mask while retaining the final
row and last delay value. The explicit endpoint is 032b, before the held-Start
test, final prompt, input wait and exit fade.

Five full-text controls agree at 6,820 semantic boundaries, 2,885 displays,
5,770 complete IRQ vectors, 1,187 polls and 579 intended writes. The genuine
perfect and ordinary success cases each have 1,448 / 610 / 1,220 / 238 / 126.
Damage, normal timeout and the historically named `win` damage control each
have 1,308 / 555 / 1,110 / 237 / 109. The existing held-button suffix is extended
to reach the complete text; there are no gameplay RAM writes. Two independently
unhooked controls agree across all 32,768 terminal bytes. Each hooked text and
startup recording separately preserves that hash. The changed terminal hashes
are not mixed with the shorter preceding recordings.

Three additional button-only controls qualify fresh Start during a name,
fresh Start during a Ski quota and a one-frame Start pulse within the first
scroll. The name and quota controls abort their pending glyph and return from
their semantic substitutions; read-only reference text-pointer observations
verify those contexts. The scroll pulse clears before the next glyph delay,
so the full instruction still finishes without skipping. These add 26 / seven /
14 / one / one; 1,165 / 486 / 972 / 216 / 104; and 1,448 / 610 / 1,220 / 238 /
126 respectively. Their combined eight-control comparison is 9,459 boundaries,
3,988 displays, 7,976 vectors, 1,642 polls and 810 intended glyph writes, zero
differences. The labels describe extensions of existing gameplay, not new
independent stunt outcomes. No common-prefix truncation is allowed.

An initial elapsed-cycle-to-frame input plan landed before the intended scroll.
It is superseded by a read-only observation of the actual containing video
frame, followed by two ordinary, unhooked button replays. The accepted scroll
recording actually observes fresh Start during a scroll wait, no skip and the
full terminal boundary. Native inputs are the resulting raw button samples;
observed operation times never become native delays.

Comparison covers semantic delay state after the layout writes its speed and
cursor state after its anchor. The inherited unused delay/cursor before those
overwrites and CPU scratch/loop registers are explicitly excluded. This is not
general CPU-state parity. Full pixels, physical bus acceptance, PCM and hardware
are not certified by intended writes or interrupt work.
